1주차 — 변수 · 자료형 · 연산자 · 조건문 · 반복문

프로그래밍의 “문장 구조”에 해당하는 부분입니다. 이 다섯 가지만 있으면 이미 웬만한 프로그램의 뼈대는 만들 수 있습니다.

이번 주 완료 기준

아래를 보지 않고 할 수 있으면 통과입니다.

  • let과 const를 상황에 맞게 골라 쓸 수 있다
  • 문자열·숫자·불리언을 구분하고 typeof로 확인할 수 있다
  • if / else if / else로 갈림길을 만들 수 있다
  • for 반복문을 직접 써서 원하는 횟수만큼 반복시킬 수 있다
  • node 파일.js로 실행하고, 에러가 나면 메시지를 읽고 원인을 짐작할 수 있다

1. 변수 — 값에 이름표를 붙이는 것

변수는 값을 담아두고 이름을 붙여놓는 상자입니다. 이름을 붙여두면 나중에 그 이름으로 꺼내 쓸 수 있습니다.

const name = "강";   // const = 한 번 정하면 바꾸지 않는 값
let age = 30;        // let  = 나중에 바뀔 수 있는 값

age = 31;            // ✅ OK — let이니까 바꿀 수 있다
// name = "김";      // ❌ TypeError: Assignment to constant variable.

=는 “같다”가 아니라 “오른쪽 값을 왼쪽 이름에 넣어라”라는 뜻입니다. 수학의 등호와 다릅니다.

💡 실무 규칙

일단 전부 const로 쓰고, 바꿔야만 하는 것만 let으로 바꾼다. 이렇게 하면 “이 값은 중간에 안 바뀌는구나”가 코드만 봐도 보여서 읽기 쉬워집니다. 실무 코드의 대부분은 const입니다.

var라는 것도 검색하면 나오는데, 옛날 문법이고 헷갈리는 동작이 많아 지금은 쓰지 않습니다. 오래된 블로그 글에서 보이면 “아 옛날 코드구나” 하고 넘기세요.

셀프 퀴즈 — 이 코드는 어떻게 될까요? 
let count = 1;
count = count + 1;
const total = 10;
total = 20;
console.log(count, total);

답: 실행되다가 total = 20; 줄에서 TypeError: Assignment to constant variable. 에러가 나며 멈춥니다. console.log는 아예 실행되지 못합니다.

여기서 중요한 건 count = count + 1이 성립한다는 점입니다. 수학에서는 말이 안 되지만, =가 “넣어라”이므로 “지금 count에 1을 더한 값을 다시 count에 넣어라”가 되어 자연스럽습니다.

2. 자료형 — 값의 “종류”

값에는 종류가 있고, 종류에 따라 할 수 있는 일이 다릅니다. 지금은 세 가지만 확실히 알면 됩니다.

const text = "문자열";   // string  — 따옴표로 감싼 글자
const num  = 42;         // number  — 따옴표 없는 숫자
const flag = true;       // boolean — true 또는 false, 딱 두 개뿐

console.log(typeof text);  // "string"
console.log(typeof num);   // "number"
console.log(typeof flag);  // "boolean"

typeof는 “이거 무슨 종류야?”라고 물어보는 도구입니다. 헷갈릴 때마다 찍어보세요.

⚠️ 가장 많이 걸리는 함정 — "42"와 42는 다르다 
42 + 1      // 43   ← 숫자 + 숫자 = 덧셈
"42" + 1    // "421" ← 문자열 + 무엇 = 이어붙이기!

JS에서 +는 숫자끼리면 더하기, 한쪽이라도 문자열이면 이어붙이기가 됩니다. 나중에 사용자 입력을 받으면 숫자처럼 보여도 실제로는 문자열 "42"인 경우가 많아, 이 함정에 반드시 한 번은 걸립니다. 그때 Number("42")로 숫자로 바꿔줍니다.

3. 연산자 — 값을 가지고 계산·비교하기

// 산술
10 + 3   // 13
10 - 3   // 7
10 * 3   // 30
10 / 3   // 3.3333...
10 % 3   // 1   ← 나머지! 나눗셈의 몫이 아니라 "남는 것"

// 비교 (결과는 항상 true 또는 false)
5 > 3      // true
5 === 5    // true   ← 같냐?
5 !== 3    // true   ← 다르냐?

// 논리
true && false  // false  ← 그리고(AND): 둘 다 참이어야 참
true || false  // true   ← 또는(OR): 하나만 참이면 참
!true          // false  ← 부정(NOT): 뒤집기

%(나머지)는 지금은 낯설지만 “짝수/홀수 판별”에 필수라 자주 씁니다. i % 2 === 0이면 2로 나눈 나머지가 0 → 짝수입니다.

⚠️ = · == · === 구별하기
  • = — 넣어라 (할당). age = 31
  • == — 느슨한 비교. "5" == 5가 true가 되어버림 (종류를 무시하고 비교)
  • === — 엄격한 비교. "5" === 5는 false (값도 종류도 같아야 참)

비교는 항상 ===, 다름은 !==를 쓰세요. ==는 예상 못한 곳에서 버그를 만듭니다. 실무 코드 리뷰에서도 ==는 지적 대상입니다.

4. 조건문 — 갈림길 만들기

const age = 20;

if (age >= 20) {
  console.log("성인");
} else {
  console.log("미성년자");
}

갈림길이 셋 이상이면 else if를 끼워넣습니다. 위에서부터 순서대로 검사해서, 처음 맞는 곳 하나만 실행하고 나머지는 건너뜁니다.

const score = 85;

if (score >= 90) {
  console.log("A");
} else if (score >= 80) {
  console.log("B");     // ← 여기서 걸리고 끝. 아래는 안 봄
} else if (score >= 70) {
  console.log("C");
} else {
  console.log("F");
}
셀프 퀴즈 — 순서를 뒤집으면?

위 코드에서 조건 순서를 >= 70, >= 80, >= 90 순으로 뒤집으면 score = 85일 때 뭐가 출력될까요?

답: "C"입니다. 85는 >= 70도 만족하므로 가장 위에서 걸려버리고 그 아래는 검사조차 하지 않기 때문입니다.

그래서 else if 사슬은 좁은 조건(엄격한 것)부터 위에 놓아야 합니다. 초보자가 자주 만드는 “왜 항상 같은 결과만 나오지?” 버그의 정체가 대개 이것입니다.

5. 반복문 — 같은 일 여러 번 시키기

1부터 5까지 출력하려고 console.log를 다섯 번 쓰는 대신, 컴퓨터에게 반복을 맡깁니다.

for (let i = 1; i <= 5; i++) {
  console.log(i);   // 1 2 3 4 5
}

for 괄호 안은 세미콜론으로 나뉜 세 부분입니다.

for ( let i = 1 ;  i <= 5 ;  i++ )
//    ①시작값     ②계속조건  ③매번 할 일
  • ① 시작값 — i를 1부터 시작 (딱 한 번만 실행)
  • ② 계속 조건 — 이게 true인 동안 계속 반복. false가 되는 순간 멈춤
  • ③ 매번 할 일 — 한 바퀴 돌 때마다 실행. i++는 i = i + 1의 줄임말

i는 index(순번)의 첫 글자로, 반복 횟수를 세는 변수에 관습적으로 붙이는 이름입니다. 매 바퀴 값이 바뀌므로 const가 아니라 let을 씁니다.

⚠️ < 와 <= 한 끗 차이 
for (let i = 1; i < 5; i++)    // 1 2 3 4   ← 5가 빠진다!
for (let i = 1; i <= 5; i++)   // 1 2 3 4 5

“하나 모자라거나 하나 더 나오는” 이 실수는 이름까지 붙어 있습니다 — off-by-one 에러. 경력자도 합니다. 결과가 이상하면 제일 먼저 여기를 의심하세요.

그리고 조건이 영원히 true가 되면 프로그램이 멈추지 않습니다(무한 루프). 터미널이 먹통이 되면 Ctrl + C로 강제 종료하세요.

📝 이번 주 과제

variables.js 파일을 만들고 아래 5개를 차례로 작성한 뒤, 터미널에서 node variables.js로 실행하세요.

복사·붙여넣기 금지. 반드시 직접 타이핑하세요. 손으로 쳐야 오타도 나고, 에러도 나고, 그 과정에서 실력이 붙습니다. 눈으로 읽어서 아는 것과 손으로 쳐서 아는 것은 완전히 다릅니다.

과제 1 — 이름과 나이 출력

const로 본인 이름을, let으로 나이를 담고 console.log로 각각 출력하세요.

힌트

1단계: 변수 두 개를 만들고, 그 아래 줄에서 console.log(변수이름)을 호출하면 됩니다.

2단계: console.log는 쉼표로 여러 개를 한 번에 찍을 수도 있습니다 — console.log(a, b)

과제 2 — 나이 1살 더하기

과제 1의 나이 변수에 1을 더해서 다시 출력하세요. (let으로 선언한 이유가 여기서 드러납니다.)

힌트

1단계: “나이에 1을 더한 값을, 다시 나이에 넣는다”를 코드로 쓰면 됩니다.

2단계: age = age + 1; — 혹은 더 짧게 age++;

과제 3 — 성인 판별

if를 써서 나이가 20 이상이면 "성인", 아니면 "미성년자"를 출력하세요.

힌트

1단계: 조건은 “나이가 20 이상”이므로 >=를 씁니다.

2단계: if (조건) { ... } else { ... } 구조에 채워 넣으세요. 중괄호 {} 짝이 맞는지 확인!

과제 4 — 1부터 10까지 출력

for 반복문으로 1, 2, 3 … 10을 차례로 출력하세요.

힌트

1단계: 위 예제의 for (let i = 1; i <= 5; i++)에서 숫자 하나만 바꾸면 됩니다.

2단계: 10이 포함되어야 하므로 <가 아니라 <=입니다.

과제 5 — 짝수만 출력 (도전)

1부터 10까지 중 짝수만 출력하세요. → 2 4 6 8 10

힌트

1단계: 과제 4의 반복문 안에 조건문을 하나 넣으면 됩니다. “돌면서, 짝수일 때만 출력”

2단계: “짝수다”를 코드로 어떻게 표현할까요? 2로 나눈 나머지가 0이면 짝수입니다.

3단계: if (i % 2 === 0) { ... }

🔒 5개 전부 다 한 뒤에 열어보세요 — 정답 & 해설

먼저 최소 15분은 스스로 시도해보세요. 막혀서 답답한 그 시간에 실력이 붙습니다. 답을 먼저 보면 “아 알겠다” 싶지만 다음에 또 못 씁니다.

// variables.js

// 과제 1
const name = "강";
let age = 30;
console.log(name, age);

// 과제 2
age = age + 1;      // age++ 와 같음
console.log(age);   // 31

// 과제 3
if (age >= 20) {
  console.log("성인");
} else {
  console.log("미성년자");
}

// 과제 4
for (let i = 1; i <= 10; i++) {
  console.log(i);
}

// 과제 5
for (let i = 1; i <= 10; i++) {
  if (i % 2 === 0) {
    console.log(i);
  }
}

왜 이렇게 되는가

  • 과제 2에서 age를 const로 선언했다면 여기서 에러가 났을 겁니다. “바뀌는 값이라 let”이라는 판단이 실제로 필요했던 순간입니다.
  • 과제 5의 핵심은 반복문 안에 조건문이 들어간다는 구조입니다. 바깥 for가 1~10을 하나씩 꺼내주고, 안쪽 if가 그중 짝수만 통과시킵니다. “거르개(필터)”를 반복문 안에 끼운 셈인데, 3주차에서 배울 filter가 정확히 이 일을 더 간단하게 해줍니다.
  • i % 2 === 0에서 ===를 썼다는 점에 주목하세요. =를 쓰면 “넣어라”가 되어 전혀 다른 동작을 합니다.

정답과 다르게 짰는데 결과가 맞다면 그것도 정답입니다. 프로그래밍에 유일한 답은 없습니다. 다만 “왜 그렇게 짰는지” 설명할 수 있어야 합니다.

💼 취업 관점 — 지금부터 들이면 좋은 습관
  • 변수 이름은 영어로, 의미가 드러나게. a, bbb, data1 ❌ → userName, totalPrice ✅. 코드는 쓰는 시간보다 읽는 시간이 훨씬 깁니다.
  • 여러 단어는 카멜케이스(camelCase). user_name이 아니라 userName — JS의 표준 관례입니다. 면접관은 이런 데서 “이 사람이 JS를 써봤나”를 봅니다.
  • 불리언 변수는 is/has로 시작. adult보다 isAdult가 “참/거짓이구나”를 즉시 알려줍니다.
  • 에러 메시지를 끝까지 읽는 습관. 빨간 글씨가 무섭다고 넘기지 마세요. TypeError: Assignment to constant variable는 이미 답을 다 말해주고 있습니다. 에러는 적이 아니라 힌트입니다.
