2주차 — 함수 · 배열 · 객체 · 스코프

1주차가 “문장”이었다면, 2주차는 “문단”입니다. 코드를 덩어리로 묶고(함수), 데이터를 뭉치로 다루는(배열·객체) 법을 배웁니다. 여기부터 진짜 프로그램처럼 보이기 시작합니다.

이번 주 완료 기준
  • 매개변수를 받아 값을 return하는 함수를 직접 만들 수 있다
  • 배열에 값을 넣고, 꺼내고, 반복문으로 전부 순회할 수 있다
  • 객체로 “하나의 사물”을 표현하고 속성에 접근할 수 있다
  • 객체가 든 배열(가장 흔한 데이터 모양)을 다룰 수 있다
  • 변수가 “어디까지 살아있는지”(스코프)를 설명할 수 있다

1. 함수 — 코드를 이름 붙여 재사용하기

변수가 값에 이름을 붙이는 것이라면, 함수는 동작에 이름을 붙이는 것입니다. 전자레인지 버튼과 같습니다 — 안에서 무슨 일이 일어나는지 몰라도, 버튼을 누르면 정해진 일이 벌어집니다.

function add(a, b) {
  return a + b;
}

const result = add(3, 5);
console.log(result);   // 8
  • add — 함수의 이름
  • (a, b) — 매개변수. 함수가 밖에서 받아오는 재료
  • return — 결과를 밖으로 돌려주기. 함수는 여기서 즉시 끝납니다
  • add(3, 5) — 호출. 실제로 실행시키는 것. a=3, b=5가 됩니다

함수를 정의하는 것과 호출하는 것은 다릅니다. 정의만 해두면 아무 일도 일어나지 않습니다. 레시피를 적어둔 것과 실제로 요리한 것의 차이입니다.

⚠️ return을 빠뜨리면 undefined 
function addWrong(a, b) {
  a + b;              // 계산은 했지만 돌려주지 않음!
}
console.log(addWrong(3, 5));   // undefined

function addRight(a, b) {
  return a + b;
}
console.log(addRight(3, 5));   // 8

undefined는 “아무것도 없음”을 뜻하는 JS의 특별한 값입니다. 함수 결과가 자꾸 undefined로 나온다면 십중팔구 return을 빠뜨린 것입니다.

console.log와 return을 헷갈리는 것도 흔합니다. console.log는 사람에게 화면으로 보여주는 것이고, return은 코드에게 값을 넘겨주는 것입니다. 완전히 다른 일입니다.

셀프 퀴즈 — 이 함수는 뭘 돌려줄까요? 
function check(n) {
  if (n > 0) {
    return "양수";
  }
  return "0 이하";
}
console.log(check(5));
console.log(check(-3));

답: "양수", "0 이하"

핵심은 return을 만나는 순간 함수가 즉시 끝난다는 점입니다. check(5)는 return "양수"에서 끝나므로 그 아래 줄은 아예 실행되지 않습니다. 그래서 else 없이도 잘 동작합니다. 이 패턴(early return)은 실무에서 코드를 얕게 유지하는 데 자주 쓰입니다.

2. 배열 — 여러 값을 순서대로 담기

변수 하나에 값 하나씩 담으면, 할 일 100개를 관리하려면 변수 100개가 필요합니다. 배열은 줄 세워 놓은 상자들입니다.

const fruits = ["사과", "바나나", "포도"];

console.log(fruits[0]);      // "사과"  ← 0번부터 시작!
console.log(fruits[2]);      // "포도"
console.log(fruits.length);  // 3       ← 개수

fruits.push("딸기");          // 뒤에 추가
console.log(fruits);         // ["사과","바나나","포도","딸기"]

fruits.pop();                // 마지막 제거
console.log(fruits.length);  // 3
⚠️ 배열은 0번부터 셉니다

첫 번째 = [0], 세 번째 = [2]. 마지막은 [length - 1]입니다. 그래서 길이 3인 배열의 마지막은 fruits[2]이고, fruits[3]은 undefined입니다 (에러가 나지 않고 조용히 undefined가 나오는 게 더 골치 아픕니다).

배열 전체를 훑을 때는 1주차의 for를 씁니다.

for (let i = 0; i < fruits.length; i++) {   // 0부터, length "미만"까지
  console.log(i, fruits[i]);
}

여기서 i = 0으로 시작하고 <=가 아니라 <를 쓰는 이유를 스스로 설명할 수 있어야 합니다. (<=를 쓰면 마지막에 undefined가 하나 더 나옵니다 — 1주차의 off-by-one 함정입니다.)

💡 더 편한 순회 — for...of 
for (const fruit of fruits) {
  console.log(fruit);      // 순번 없이 값만 필요할 때
}

순번 i가 필요 없다면 이쪽이 훨씬 읽기 좋습니다. 실수할 여지(off-by-one)도 아예 없습니다.

3. 객체 — 하나의 사물을 표현하기

배열이 “같은 것 여러 개”라면, 객체는 “한 사물의 여러 속성”입니다. 사람 한 명에게는 이름·나이·직업이 있습니다.

const user = {
  name: "강",
  age: 30,
  isStudent: true,
};

console.log(user.name);      // "강"     ← 점 표기법
console.log(user["age"]);    // 30       ← 대괄호 표기법 (거의 안 씀)

user.age = 31;               // 수정
user.city = "서울";           // 새 속성 추가
console.log(user);

name: 부분을 키(key), "강" 부분을 값(value)이라고 부릅니다. 사전에서 단어를 찾듯 키로 값을 찾는 구조입니다.

⚠️ const인데 왜 수정이 되지?

user를 const로 선언했는데도 user.age = 31이 동작합니다. 이상해 보이지만 규칙은 일관됩니다.

const가 막는 것은 “그 이름표를 다른 것에 다시 붙이는 것”뿐입니다. 상자 안의 내용물을 바꾸는 건 막지 않습니다.

user.age = 31;              // ✅ 상자 속 내용 변경 — OK
user = { name: "김" };       // ❌ 이름표를 다른 상자에 붙임 — TypeError

배열도 완전히 동일합니다. const 배열에 push는 되지만 = [](재할당)은 안 됩니다.

가장 흔한 데이터 모양 — 객체가 든 배열

실무에서 서버로부터 받는 데이터는 거의 항상 이 모양입니다. 지금 익숙해지면 나중에 API를 다룰 때 훨씬 수월합니다.

const todos = [
  { id: 1, title: "JS 공부", done: true },
  { id: 2, title: "운동",    done: false },
  { id: 3, title: "장보기",  done: false },
];

for (const todo of todos) {
  const mark = todo.done ? "✅" : "⬜";   // 삼항 연산자
  console.log(mark, todo.title);
}

조건 ? A : B는 삼항 연산자로, “조건이 참이면 A, 아니면 B”라는 if/else의 짧은 버전입니다. 값을 고를 때만 쓰고, 복잡해지면 그냥 if를 쓰세요.

4. 스코프 — 변수가 살아있는 범위

변수는 아무 데서나 보이는 게 아닙니다. 중괄호 {} 안에서 선언된 변수는 그 안에서만 살아있습니다.

function test() {
  const inside = "함수 안";
  console.log(inside);     // ✅ 보임
}

test();
// console.log(inside);    // ❌ ReferenceError: inside is not defined
if (true) {
  const blockVar = "블록 안";
}
// console.log(blockVar);  // ❌ 역시 안 보임

for (let i = 0; i < 3; i++) { }
// console.log(i);         // ❌ i도 for 밖에선 안 보임

불편해 보이지만 이건 기능입니다. 함수마다 i를 마음 놓고 쓸 수 있고, 서로 이름이 부딪히지 않습니다. 변수가 사방에서 보이면 “누가 이 값을 바꿨는지” 추적이 불가능해집니다.

셀프 퀴즈 — 뭐가 출력될까요? 
const message = "바깥";

function show() {
  const message = "안쪽";
  console.log(message);
}

show();
console.log(message);

답: "안쪽" 다음 "바깥"

같은 이름이지만 서로 다른 변수 두 개입니다. 함수 안에서는 “가장 가까운” 안쪽 변수가 바깥 것을 가립니다(shadowing). 함수가 끝나면 안쪽 message는 사라지고, 바깥 것은 처음부터 아무 영향도 받지 않았습니다.

안쪽에서 const message를 지우면 어떻게 될까요? 그때는 안쪽에 없으니 바깥을 찾아 올라가서 "바깥"이 두 번 출력됩니다. 이렇게 안에서 밖으로 찾아 올라가는 것을 스코프 체인이라고 합니다.

todo.js 파일을 만들고 아래를 차례로 완성하세요. 5개를 다 하면 작은 프로그램 하나가 완성됩니다. 커리큘럼의 “콘솔 미니 프로그램” 첫 번째 결과물입니다.

복사·붙여넣기 금지. 직접 타이핑하세요. 그리고 과제 하나 끝낼 때마다 node todo.js로 실행해서 확인하세요. 다섯 개를 몰아서 짜고 마지막에 실행하면, 에러가 났을 때 어디가 문제인지 찾기 훨씬 어려워집니다.

과제 1 — 인사 함수

이름을 매개변수로 받아 "안녕하세요, 강님!" 형태의 문자열을 return하는 greet 함수를 만드세요. (출력이 아니라 반환입니다.) 그리고 호출 결과를 console.log로 찍으세요.

힌트

1단계: function greet(name) { ... } 안에서 문자열을 만들어 return합니다.

2단계: 문자열 붙이기는 "안녕하세요, " + name + "님!"

3단계: 더 깔끔한 방법 — 백틱(`)을 쓰는 템플릿 리터럴: `안녕하세요, ${name}님!`. 실무에서는 이쪽을 훨씬 많이 씁니다.

과제 2 — 할 일 배열 만들고 전부 출력

객체 3개가 든 todos 배열을 만드세요. 각 객체는 id, title, done 속성을 가집니다. 그리고 반복문으로 전부 출력하세요.

힌트

1단계: 위 “객체가 든 배열” 예제의 모양을 참고하되, 내용은 본인의 실제 할 일로 채우세요.

2단계: 순회는 for (const todo of todos) { ... }

과제 3 — 완료 표시해서 예쁘게 출력

각 할 일을 [✅] JS 공부 / [⬜] 운동 형태로 출력하세요. done이 true면 ✅, 아니면 ⬜.

힌트

1단계: 반복문 안에서 if/else로 표시 문자를 정한 뒤 출력하면 됩니다.

2단계: 삼항 연산자를 쓰면 한 줄로 — const mark = todo.done ? "✅" : "⬜";

과제 4 — 할 일 추가 함수

배열과 제목을 받아, 새 할 일 객체를 배열에 추가하는 addTodo(list, title) 함수를 만드세요. 새 항목의 done은 false, id는 겹치지 않게 정하세요.

힌트

1단계: 함수 안에서 객체를 하나 만들고, list.push(새객체)로 넣습니다.

2단계: id를 어떻게 정할까요? 현재 개수를 이용하면 됩니다 — list.length + 1

3단계: 호출한 뒤 과제 3의 출력을 다시 돌려서 새 항목이 보이는지 확인하세요.

과제 5 — 완료 개수 세기 (도전)

배열을 받아 완료된 할 일의 개수를 return하는 countDone(list) 함수를 만드세요. 그리고 "3개 중 1개 완료" 형태로 출력하세요.

힌트

1단계: “세기”는 항상 같은 패턴입니다 — 0으로 시작하는 카운터 변수를 만들고, 돌면서 조건에 맞을 때만 1씩 더한 뒤, 마지막에 반환.

2단계: 카운터는 값이 변하므로 let count = 0;

3단계: if (todo.done) { count++; } — todo.done === true라고 써도 되지만, 이미 불리언이므로 그냥 todo.done으로 충분합니다.

4단계: return count;를 반복문 밖에 두세요. 안에 두면 첫 바퀴에서 함수가 끝나버립니다.

🔒 5개 전부 다 한 뒤에 열어보세요 — 정답 & 해설

먼저 최소 20분은 스스로 시도해보세요. 특히 과제 5는 “세기” 패턴을 몸에 익히는 게 목적이라, 답을 보면 얻는 게 거의 없습니다.

// todo.js

// 과제 1
function greet(name) {
  return `안녕하세요, ${name}님!`;
}
console.log(greet("강"));

// 과제 2
const todos = [
  { id: 1, title: "JS 공부", done: true },
  { id: 2, title: "운동",    done: false },
  { id: 3, title: "장보기",  done: false },
];

// 과제 3
function printTodos(list) {
  for (const todo of list) {
    const mark = todo.done ? "✅" : "⬜";
    console.log(`[${mark}] ${todo.title}`);
  }
}
printTodos(todos);

// 과제 4
function addTodo(list, title) {
  const newTodo = { id: list.length + 1, title: title, done: false };
  list.push(newTodo);
}
addTodo(todos, "책 읽기");
printTodos(todos);

// 과제 5
function countDone(list) {
  let count = 0;
  for (const todo of list) {
    if (todo.done) {
      count++;
    }
  }
  return count;          // ← 반복문 밖!
}
console.log(`${todos.length}개 중 ${countDone(todos)}개 완료`);

왜 이렇게 되는가

  • 출력을 printTodos 함수로 묶은 이유: 과제 4에서 또 출력해야 했기 때문입니다. 같은 코드를 두 번 쓰게 되는 순간이 바로 “함수로 뽑을 때”라는 신호입니다. 이 감각이 함수를 배우는 진짜 이유입니다.
  • 과제 5의 return 위치가 핵심입니다. 반복문 안에 두면 첫 바퀴에서 즉시 함수가 끝나 항상 0이나 1만 나옵니다. return은 “함수를 끝낸다”는 걸 다시 확인하세요.
  • { title: title }이 어색하다면 맞습니다. JS에는 줄임 문법이 있어 키와 변수 이름이 같으면 { title }로 쓸 수 있습니다. 3주차에서 다룹니다.
  • addTodo가 아무것도 return하지 않는데 동작하는 이유: 배열을 “복사해서” 넘긴 게 아니라 원본을 가리키는 주소를 넘겼기 때문입니다. 그래서 함수 안에서 push하면 바깥 배열이 실제로 바뀝니다. 이것을 참조(reference)라고 하며, 3주차 스프레드 문법에서 다시 만납니다.

과제 5를 filter로 한 줄에 끝내는 방법이 있는데, 그게 바로 다음 주 내용입니다. 지금 for로 직접 짜본 경험이 있어야 filter가 왜 편한지 체감됩니다.

💼 취업 관점
  • 함수 이름은 동사로. todoAdd보다 addTodo, doneCount보다 countDone. 함수는 “하는 일”이므로 동사가 앞에 옵니다.
  • 함수 하나는 한 가지 일만. countDone이 세면서 출력까지 하면, 다른 데서 “세기만” 하고 싶을 때 못 씁니다. 계산하는 함수와 보여주는 함수를 분리하는 것은 React·RN에서도 그대로 이어지는 원칙입니다.
  • 문자열은 템플릿 리터럴로. "a" + b + "c"보다 `a${b}c`가 읽기 쉽고, 실무 코드에서 압도적으로 많이 쓰입니다.
  • “객체가 든 배열”은 앞으로 계속 나옵니다. 서버 응답, 화면에 뿌릴 목록, RN의 FlatList 데이터 — 전부 이 모양입니다. 지금 익숙해지면 뒤가 편합니다.
