3주차 — 배열 메서드 · 구조분해 · 스프레드 · 비동기

여기가 “JS를 쓸 줄 안다”의 분기점입니다. 이번 주 문법은 React·React Native 코드에서 거의 매 줄 등장합니다. 2주차에 for로 힘들게 짰던 걸 한 줄로 줄이는 법을 배웁니다.

이번 주 완료 기준
  • 화살표 함수를 읽고 쓸 수 있다
  • map / filter / reduce를 언제 쓰는지 구분할 수 있다
  • 구조분해로 객체·배열에서 값을 꺼낼 수 있다
  • 스프레드로 배열·객체를 복사하며 바꿀 수 있다
  • async/await로 비동기 코드를 순서대로 읽히게 쓸 수 있다
  • fetch로 실제 인터넷 데이터를 받아올 수 있다

1. 화살표 함수 — 함수를 짧게 쓰는 법

하는 일은 2주차의 function과 같습니다. 모양만 짧습니다.

// 2주차 방식
function add(a, b) {
  return a + b;
}

// 화살표 함수
const add = (a, b) => {
  return a + b;
};

// 본문이 "값 하나 반환"뿐이면 중괄호와 return 생략 가능
const add = (a, b) => a + b;

// 매개변수가 하나면 괄호도 생략 가능
const double = n => n * 2;
⚠️ 중괄호를 쓰면 return이 필요합니다 
const double = n => n * 2;         // ✅ 2를 곱해 반환
const double = n => { n * 2; };    // ❌ undefined! (계산만 하고 안 돌려줌)
const double = n => { return n * 2; };  // ✅ 중괄호를 썼으면 return 필수

“중괄호가 없으면 자동 반환, 있으면 return을 직접 써야 한다” — 이 규칙 하나만 기억하면 됩니다.

왜 이렇게 짧게 쓰냐면, 다음에 배울 map·filter에 함수를 통째로 인자로 넘기기 때문입니다. 그때 function을 다 쓰면 코드가 지저분해집니다.

2. map — 전부 다른 모양으로 바꾸기

map은 모든 요소를 하나씩 변환해서 “같은 길이의 새 배열”을 만듭니다. 붕어빵 틀에 반죽을 넣으면 개수는 그대로, 모양만 바뀌는 것과 같습니다.

const numbers = [1, 2, 3, 4];

// 2주차 방식
const doubled = [];
for (const n of numbers) {
  doubled.push(n * 2);
}

// map — 한 줄
const doubled = numbers.map(n => n * 2);   // [2, 4, 6, 8]
const todos = [
  { id: 1, title: "JS 공부", done: true },
  { id: 2, title: "운동",    done: false },
];

const titles = todos.map(todo => todo.title);   // ["JS 공부", "운동"]

3. filter — 조건에 맞는 것만 골라내기

filter는 조건이 true인 것만 남긴 새 배열을 만듭니다. 개수가 줄어듭니다(모양은 그대로).

const numbers = [1, 2, 3, 4, 5, 6];

const evens = numbers.filter(n => n % 2 === 0);   // [2, 4, 6]

const doneTodos = todos.filter(todo => todo.done);          // 완료된 것만
const doneCount = todos.filter(todo => todo.done).length;   // 2주차 과제 5가 한 줄로!
💡 map vs filter — 한 문장 구분법

map은 개수가 그대로, 내용이 바뀐다. filter는 내용이 그대로, 개수가 줄어든다.

둘 다 원본을 건드리지 않고 새 배열을 돌려줍니다. 이 성질이 React·RN에서 결정적으로 중요해집니다 — 화면 갱신이 “원본이 바뀌었는지”가 아니라 “새것이 왔는지”로 판단되기 때문입니다.

셀프 퀴즈 — 이어 붙이면? 
const nums = [1, 2, 3, 4, 5, 6];
const result = nums.filter(n => n % 2 === 0).map(n => n * 10);
console.log(result);

답: [20, 40, 60]

filter가 새 배열을 돌려주므로, 그 결과에 곧바로 .map을 이어 붙일 수 있습니다(체이닝). “짝수만 고른 뒤 → 각각 10배”가 코드에 그대로 읽힙니다. for로 짜면 여러 줄이 필요한 일입니다.

순서를 바꿔 .map(n => n * 10).filter(n => n % 2 === 0)으로 하면? 10을 곱하면 전부 짝수가 되므로 [10,20,30,40,50,60]이 나옵니다. 순서가 결과를 바꿉니다.

4. reduce — 전부 합쳐서 하나로

map·filter가 배열 → 배열이라면, reduce는 배열 → 값 하나입니다. 합계, 평균, 최댓값처럼 “뭉쳐서 하나로 만드는” 일에 씁니다.

const prices = [1000, 2500, 3000];

const total = prices.reduce((sum, price) => sum + price, 0);
//                           ↑     ↑                    ↑
//                        누적값  현재값            시작값(0)
console.log(total);   // 6500

동작을 풀어 보면 이렇습니다.

시작:  sum = 0
1바퀴: sum = 0    + 1000 = 1000
2바퀴: sum = 1000 + 2500 = 3500
3바퀴: sum = 3500 + 3000 = 6500  ← 최종 반환

reduce는 셋 중 가장 어렵습니다. 지금은 “합계 구할 때 쓰는 것” 정도로만 알아도 충분합니다. 실무에서도 빈도는 map ≫ filter ≫ reduce 순입니다.

⚠️ 시작값 0을 빠뜨리지 마세요

reduce의 두 번째 인자(, 0)를 빠뜨리면 빈 배열에서 TypeError: Reduce of empty array with no initial value가 납니다. 평소엔 잘 돌다가 데이터가 비었을 때만 터지는, 찾기 어려운 버그가 됩니다.

5. 구조분해 — 필요한 값만 꺼내 오기

const user = { name: "강", age: 30, city: "서울" };

// 예전 방식
const name = user.name;
const age = user.age;

// 구조분해 — 한 줄
const { name, age } = user;
console.log(name, age);   // "강" 30

배열도 됩니다. 이쪽은 순서로 꺼냅니다.

const colors = ["빨강", "파랑", "초록"];
const [first, second] = colors;
console.log(first, second);   // "빨강" "파랑"

함수 매개변수에서 바로 쓰면 특히 깔끔합니다. React 컴포넌트가 props를 받는 방식이 정확히 이것입니다.

function printUser({ name, age }) {     // 객체를 받아 그 자리에서 분해
  console.log(`${name}(${age}세)`);
}
printUser(user);   // "강(30세)"

6. 스프레드 ... — 펼쳐서 복사하기

...은 배열·객체를 펼쳐서 새것을 만듭니다.

const a = [1, 2];
const b = [3, 4];
const merged = [...a, ...b];        // [1, 2, 3, 4]
const added  = [...a, 99];          // [1, 2, 99]  ← a는 그대로!

const user = { name: "강", age: 30 };
const older = { ...user, age: 31 }; // { name: "강", age: 31 }
//                       ↑ 뒤에 쓴 것이 이김 = 덮어쓰기
⚠️ 이게 왜 중요한가 — 원본을 바꾸지 않는다 
// ❌ 원본을 직접 수정 (mutation)
todos.push(newTodo);
user.age = 31;

// ✅ 새것을 만든다 (immutable)
const nextTodos = [...todos, newTodo];
const nextUser  = { ...user, age: 31 };

2주차에서 push가 원본 배열을 바꾼다는 걸 봤습니다. React와 React Native는 “새 배열/객체가 왔는지”로 화면 갱신을 판단하기 때문에, 원본을 직접 바꾸면 데이터는 바뀌었는데 화면이 안 바뀌는 유명한 버그가 생깁니다.

지금부터 “바꾸지 말고 새로 만든다”를 습관으로 들이면 단계 2~3에서 이 버그를 겪지 않습니다.

7. 비동기 — 시간이 걸리는 일 다루기

지금까지의 코드는 전부 즉시 끝났습니다. 하지만 인터넷에서 데이터를 받아오는 일은 시간이 걸립니다(0.1초일 수도, 3초일 수도). 이때 JS는 기다리지 않고 다음 줄로 넘어갑니다.

console.log("1. 주문");
setTimeout(() => console.log("2. 음식 나옴"), 2000);   // 2초 뒤
console.log("3. 다른 일 하기");

// 출력 순서: 1. 주문 → 3. 다른 일 하기 → (2초 후) 2. 음식 나옴

식당에서 주문하고 진동벨을 받는 것과 같습니다. 음식이 나올 때까지 카운터 앞에 서 있지 않고, 자리에 앉아 다른 일을 합니다. 이 “진동벨”에 해당하는 것이 Promise입니다 — “나중에 결과를 주겠다”는 약속.

async / await — 기다렸다가 받기

async function getUser() {
  const res  = await fetch("https://jsonplaceholder.typicode.com/users/1");
  const data = await res.json();
  console.log(data.name);
}
getUser();
  • await — “이거 끝날 때까지 여기서 기다려”
  • async — “이 함수 안에서 await를 쓰겠다”는 표시. await는 async 함수 안에서만 쓸 수 있습니다

await 덕분에 비동기 코드가 위에서 아래로 순서대로 읽힙니다. 이게 async/await의 전부이자 존재 이유입니다.

에러 처리 — try / catch

인터넷은 끊깁니다. 서버는 죽습니다. 비동기 코드에는 실패 대비가 필수입니다.

async function getUser() {
  try {
    const res  = await fetch("https://jsonplaceholder.typicode.com/users/1");
    const data = await res.json();
    console.log(data.name);
  } catch (error) {
    console.log("실패했어요:", error.message);
  }
}

try 안에서 문제가 생기면 즉시 catch로 점프합니다. 프로그램이 죽는 대신 “실패했어요”를 보여줄 기회를 얻습니다. 단계 4에서 앱의 로딩·에러 화면을 만들 때 그대로 쓰게 됩니다.

과제 3 — 10만 원 이하 상품 이름

2단계: products.filter(...).map(...) — 순서가 중요합니다. 왜 map을 먼저 하면 안 될까요? (이름만 남으면 가격 정보가 사라집니다.)

과제 4 — 재고 상품 총액 (도전)

filter와 reduce로 재고 있는 상품들의 가격 합계를 구해 출력하세요.

힌트

1단계: 먼저 재고 있는 것만 거릅니다.

2단계: 그 배열에 .reduce((sum, p) => ..., 0)을 붙입니다.

3단계: 누적할 것은 p 전체가 아니라 p.price입니다 → sum + p.price. 시작값 0을 잊지 마세요.

과제 5 — 진짜 인터넷 데이터 가져오기 (도전 · 별도 파일)

fetch-user.js를 만들어 https://jsonplaceholder.typicode.com/users에서 사용자 목록을 받아, 이름과 이메일만 출력하세요. try/catch로 에러 처리도 넣으세요.

실행: node fetch-user.js — Node 24에는 fetch가 내장되어 있어 설치할 것이 없습니다.

힌트

1단계: async function main() { ... }을 만들고 맨 아래에서 main();으로 호출합니다.

2단계: const res = await fetch(주소); 다음 const users = await res.json(); — await 두 번이 필요합니다(응답 도착 대기 → 본문 해석 대기).

3단계: users는 객체가 든 배열입니다. 먼저 console.log(users[0])로 어떤 모양인지 눈으로 확인한 뒤 필요한 키를 꺼내세요. 모르는 데이터를 만나면 항상 이렇게 시작합니다.

4단계: map이나 for...of로 user.name, user.email을 출력하면 됩니다.

🔒 5개 전부 다 한 뒤에 열어보세요 — 정답 & 해설

특히 과제 5는 “모르는 데이터를 찍어보며 파악하는” 과정 자체가 훈련입니다. 답을 먼저 보면 그 훈련을 통째로 건너뛰게 됩니다.

// array-methods.js

// 과제 1
const names = products.map(p => p.name);
console.log(names);

// 과제 2
const inStockProducts = products.filter(p => p.inStock);
console.log(`재고 있는 상품 ${inStockProducts.length}개:`, inStockProducts.map(p => p.name));

// 과제 3
const cheapNames = products
  .filter(p => p.price <= 100000)
  .map(p => p.name);
console.log(cheapNames);        // ["마우스", "키보드", "웹캠"]

// 과제 4
const totalPrice = products
  .filter(p => p.inStock)
  .reduce((sum, p) => sum + p.price, 0);
console.log(`재고 총액: ${totalPrice.toLocaleString()}원`);   // 1,545,000원
// fetch-user.js

async function main() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/users");
    const users = await res.json();

    for (const user of users) {
      console.log(`${user.name} — ${user.email}`);
    }
  } catch (error) {
    console.log("불러오기 실패:", error.message);
  }
}

main();

왜 이렇게 되는가

  • 과제 3에서 filter가 먼저인 이유: map을 먼저 하면 배열이 이름 문자열만 남아 p.price로 거를 수 없습니다. 거르기 → 변환하기 순서가 거의 항상 맞습니다(불필요한 변환도 줄어듭니다).
  • 체이닝을 여러 줄로 나눈 것에 주목하세요. .filter(...).map(...)이 길어지면 . 앞에서 줄바꿈하는 것이 실무 관례입니다. 읽기 훨씬 좋습니다.
  • await가 두 번인 이유: fetch는 “응답 헤더가 도착”하면 끝나고, 본문을 JSON으로 해석하는 res.json()이 또 시간이 걸리는 작업이기 때문입니다. 하나라도 빠뜨리면 Promise { <pending> }이라는 이상한 것이 찍히는데, 그게 보이면 await를 빠뜨린 것입니다.
  • main()을 맨 아래에서 호출하는 이유: async function은 정의만으로는 실행되지 않습니다(2주차의 정의 vs 호출과 동일).
  • toLocaleString()은 1545000을 1,545,000으로 바꿔주는 내장 기능입니다. 몰라도 되지만 알아두면 숫자 표시에 계속 씁니다.
💼 취업 관점 — 이번 주가 특히 중요한 이유
  • React·RN 코드는 이 문법 위에 세워져 있습니다. 화면에 목록을 그리는 건 map, props를 받는 건 구조분해, 상태를 갱신하는 건 스프레드입니다. 이번 주를 대충 넘기면 단계 2~3에서 “문법이 안 읽혀서” 막힙니다.
  • “원본을 바꾸지 않는다(불변성)”는 면접 단골 주제입니다. “왜 push 대신 스프레드를 쓰나요?”에 답할 수 있어야 합니다. 답: React가 참조 비교로 변경을 감지하기 때문.
  • for보다 map/filter를 선호합니다. 의도가 이름에 드러나기 때문입니다 — filter를 보는 순간 “거르는구나”를 압니다. 코드 리뷰에서 자주 지적되는 부분입니다.
  • 에러 처리를 빼먹지 마세요. 신입 포트폴리오에서 가장 흔한 감점 요인이 “네트워크 실패를 고려하지 않은 코드”입니다. try/catch 하나가 인상을 바꿉니다.
